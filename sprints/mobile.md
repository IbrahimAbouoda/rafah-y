## الواجهة — المرحلة A

**الهوية:** `Authorization: Bearer <رمز وصول Supabase>` ← `lib/api/auth.ts` يتحقق عند Supabase ثم `provisionUser` ←
`loadSessionUser` (المسار نفسه للكوكي). **الغلاف:** `lib/api/handler.ts` — `apiRoute({ auth })`، والأخطاء
`{ error: { code, message_ar, field_errors? } }` بالرسالة العربية نفسها (`toErrorInfo()` مشتركة مع `runAction`)،
و 429 مع `Retry-After`، و `Cache-Control: no-store` لكل استجابة. **الترقيم:** `?page=&pageSize=` كالويب.

**قرارات تنفيذ تحتاج علمكم:**

- **ثغرة أُغلقت:** ملف الشكوى الداخلي وقائمة المجلس كانا محميين بـ `guardPage(…, { beyondOwn })` في الصفحة فقط.
  عبر الواجهة كان مقدّم الشكوى سيقرأ أحداثها الداخلية وأسماء المنفّذين. الفحص الآن داخل `complaintFile()` و `complaintList()`،
  وكذلك اللجان والمؤسسات والتدقيق.
- **ملاحظة المراجعة الداخلية للفكرة** كانت تُجلب للصفحة العامة وتُخفى عند العرض؛ الآن لا تغادر الخادم إلا لمن يملك `ideas:read_internal`.
- **المصادقة عبر الخادم (D46)** لا عبر `supabase_flutter` مباشرة: وإلا تجاوز التطبيق حد التسجيل والحظر المتضاعف وقواعد كلمة المرور.
